## 증상별 확인

| 증상 | 먼저 확인할 내용 |
| --- | --- |
| 지도 인증 오류·빈 지도 | Maps Client ID, Dynamic Map 사용 설정, 콘솔 Web URL의 `http://localhost` 등록. 포트·경로는 제외 |
| 좌표는 이동하지만 장소명을 찾지 못함 | API HUB의 지역 검색 사용 설정과 별도 Client ID / Client Secret |
| 주소 검색만 실패 | Maps의 Geocoding 사용 설정과 지도 SDK 인증 |
| 경로 생성만 실패 | Maps의 Directions 5 사용 설정과 Client ID / Client Secret |
| 설정 메뉴에서 키를 바꿔도 적용되지 않음 | 환경변수가 우선. QGIS 실행 환경의 변수와 현재 프로필 확인 후 재시작 |
| 내장 웹 뷰 대신 외부 연동 화면이 나옴 | Qt WebEngine/WebChannel 사용 가능 여부. 외부 연동 창 열기로 계속 사용 가능 |
| 외부 탭은 열리지만 연동되지 않음 | QGIS를 켜 두고 플러그인 버튼에서 새 탭 실행. 이전 세션 탭 종료 |
| 기본 포트 8083 사용 중 | 자동으로 별도 포트 사용. 플러그인이 연 주소 사용. 서버 두 개를 같은 포트에 고정하지 않음 |
| EN인데 지명이 한글 | 기존 한글 이력인지 확인. EN 선택 후 새 경로를 생성해야 API 영문 지명을 요청 |
| KR인데 안내가 영어 | 영어로 생성한 저장 원문은 유지됨. 한글 안내가 필요하면 KR에서 새 경로 생성 |
| 탐색창 접기 후 이력이 보이지 않음 | 2026-10-27 fix4 또는 이후 수정본인지 확인. 새 ZIP 설치 후 QGIS와 외부 탭 재시작 |
| 이력 재불러오기 실패 | GPKG 또는 경로·안내 파일 쌍 확인. 이전 좌표 정밀도 문제 수정본인지 확인 |
| SHP 저장 중 긴 문자열 오류 | GeoPackage/GeoJSON으로 저장. 한글 UTF-8 폭·경유지 정보의 필드 한도 확인 |
| QGIS와 지도 축척 숫자가 조금 다름 | NAVER의 이산 줌 단계에 따른 차이. 반복 이동·진동이 없다면 숫자만으로 실패로 판단하지 않음 |

## 연결과 요청 복구

외부 연동은 로컬 서버의 세션 인증을 사용합니다. 이전 탭을 새 QGIS 세션에 연결하거나 토큰 없는 주소를 직접 입력하면 명령이 거부될 수 있습니다. QGIS를 종료한 상태에서는 브라우저 지도 화면이 남아도 연동되지 않습니다.

경로 탐색 중에는 **취소**를 사용합니다. 위치 검색과 경로 API 요청은 서로 다른 단계이므로 네트워크 상태에 따라 대기 시간이 다를 수 있습니다. 시간 초과 후 입력창이 복구되면 설정·연결을 확인하고 다시 조회합니다.

키의 서비스·권한·사용량 제한은 [Maps 공식 문제 해결](https://guide.ncloud-docs.com/docs/application-maps-troubleshoot)과 [API HUB 공식 문서](https://api.ncloud-docs.com/docs/naver-api-hub-overview)를 확인하세요. 한 종류의 키를 다른 서비스 키로 교체하는 방식으로 해결하지 않습니다.

## 오류 보고

[GitHub Issues](https://github.com/youngj-kim/navermap_qgis-bridge/issues)에 아래 정보를 남겨 주세요. Client ID / Client Secret과 외부 뷰어 URL의 세션 토큰은 지우고 공유합니다.

```text
플러그인 버전 / 설치 ZIP 이름:
QGIS 버전 / 운영체제:
내장 웹 뷰 또는 외부 브라우저 / 브라우저 버전:
재현 순서:
기대 결과 / 실제 결과:
오류 메시지 (키·세션 토큰 제외):
```

인증 정보가 포함된 QGIS 설정 파일이나 완성된 뷰어 HTML을 첨부하지 마세요. 재현을 위해 이력 파일이 필요하다면 위치·주소 등 민감한 데이터가 없는 예시를 준비합니다.
