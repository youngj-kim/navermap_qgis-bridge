# 카카오 기능 비교 후 순차 적용 기록

## 2026-10-15 검토 수정 및 사용자 확인

안내 코드 매핑·기존 이력 분류 보정, 외부 브리지 인증/출처/콘텐츠 타입/독점 소켓·대체 포트, 응답·키 검증, 이력 실패 복구와 가져오기 검증, 내보내기 데이터 손실 방지, 이벤트 처리와 동기화 누락을 수정했다. Python 67개·웹 회귀·QGIS 3.44.14/4.2.2 오프라인 검증 결과는 루트 `TESTING.md`에 기록했다.

사용자는 2026-10-15 수정본에 이상이 없다고 확인했다. 실행한 QGIS 버전·브라우저 모드와 개별 시나리오는 명시되지 않았으므로 전체 환경 매트릭스의 통과로 간주하지 않는다. 메타데이터 `0.2.0`과 GPL-2.0-or-later를 유지한다. 커밋에는 소스·테스트·문서를 포함하고 설치 ZIP·로컬 설정·운영 키는 제외한다.


날짜: 2026-10-13. 기존 미커밋 변경을 유지한 작업 트리에 순서대로 적용했다. 메타데이터 `0.2.0`과 GPL-2.0-or-later를 유지한다. 새 외부 라이브러리·이미지·카카오 소스는 포함하지 않았다. 실제 키·사용자 프로젝트를 사용하지 않았다.

## 적용한 묶음

### 사용자 테스트 후 보완

- 사용자가 QGIS 4.2.2에서 나머지 수정 사항의 적용을 확인했다. 후속 수정은 상단 탐색창 버튼·배치 선택·전체화면을 한 줄로 유지하는 레이아웃에 한정한다. 좁은 화면용 배치 선택 `width:100%` 규칙과 줄바꿈을 제거하고 선택 상자가 남는 폭을 사용하게 했다.

- NAVER 지도 이동에서 로드뷰를 직접 갱신하는 처리를 추가했다. 드래그 중에는 QGIS 위치를 전달하고 드래그 종료 시 로드뷰를 갱신한다. 중간 이벤트가 같은 좌표를 기록했어도 종료 이벤트를 누락하지 않으며, 전달 오류 후 동일 좌표 재시도를 허용한다. QGIS 호출은 로드뷰 이동과 같은 두 인자 형식으로 통일했다.
- 탐색창 접기 버튼·뷰 배치·전체화면을 항상 보이는 툴바에 배치했다.
- 사용자 요청에 따라 검색 결과 펼치기/접기 버튼을 제거했다. 결과는 검색 시 표시하고 선택/지도 클릭 시 숨긴다.
- 공식 Directions 5/15 명세를 다시 확인했다. 하이패스 보유 여부/전용 경로 선택 파라미터는 없지만 안내 코드 122로 하이패스 전용 톨게이트를 표현할 수 있다. UI 설명을 경로 설정 미지원으로 구체화했다.

아래 묶음은 최초 적용 기록이다. 검색 결과 접기/재표시 기능은 위 사용자 요청으로 제거했다.

1. **설정 정확성과 검색:** 복수 회피 선택 방지 및 요청 경계 검증, 실제 회피 옵션으로 결과/이력 표시, 하이패스 비활성화·이륜차 제거, 좌표 검색 후 이전 장소 응답 차단. 과거 연료 대문자 값과 잘못된 차량 설정을 읽을 때 안전한 기본값으로 복구한다.
2. **요청과 프로젝트 수명:** 취소 버튼, API 30초 제한과 웹 35초 복구, 위치 해석 중 취소, 프로젝트 전환 시 요청 취소·현재 표시 초기화·세션 이력 유지. 외부 HTTP 세대 검증·입력 경로 제한·본문/큐 제한, 파일 대화상자 복귀 시 세대 확인.
3. **지도 사용성:** 탐색창·검색 결과 접기/재표시, 일반/위성/위성+지명, 로드뷰 촬영 도로 토글. 첫 분리창은 화면 범위 내에서 1100×850 기준으로 열고 재도킹 시 SDK 크기를 갱신한다.
4. **확대·축소:** QGIS와 NAVER 모두 128픽셀 구간의 지상 거리를 사용한다. QGIS→웹은 가장 가까운 정수 줌을 적용하고 웹→QGIS는 캔버스 확대 비율을 계산한다. 줌만 변경하면 로드뷰 위치/마커를 유지하고, 일반 이동은 기존 위치 연동을 유지한다. 같은 뷰의 반복 이벤트는 생략한다.
5. **리팩터링:** 경로 입력 검증을 순수 함수로, 이력 스키마를 공통 정의로, 지도 표시 옵션을 명시적 의존성을 받는 JS 모듈로 분리했다. 파일 필드 순서·SHP 단축명·GPX 확장은 유지한다.

## 검증 묶음

`tests/run_checks.py`로 `core`, `web`, `qgis` 묶음을 실행한다. 실패하면 해당 명령에서 중단하며 의존성을 자동 설치하지 않는다. `qgis` 묶음은 실제 설치된 실행기를 명시해야 한다.

```powershell
python -B tests/run_checks.py --group core --group web
python -B tests/run_checks.py --group qgis --qgis-launcher 'C:\Program Files\QGIS 3.44.14\bin\python-qgis-ltr.bat' --qgis-launcher 'C:\Program Files\QGIS 4.2.2\bin\python-qgis.bat'
```

웹 검사에는 테스트 전용 Playwright가 필요하다. 설치된 Chrome을 쓰면 `TEST_BROWSER_CHANNEL=chrome`, 별도 패키지 경로를 쓰면 `NODE_PATH`를 설정한다. 기본 Python alias가 실행되지 않는 이 PC에서는 Codex 번들 Python을 사용했다. 최종 실행 결과는 `TESTING.md`에 기록한다.

SDK 구현 근거: [NAVER Map](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Map.html), [StreetLayer](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.StreetLayer.html), [MapSystemProjection](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.MapSystemProjection.html). 경로 설정 범위는 [Directions 5](https://api.ncloud-docs.com/docs/application-maps-directions5)를 확인했다.

## 남은 검증과 후속 확장

- **필수 미검증:** 정확한 QGIS 3.34 런타임, 실제 NAVER 인증·검색·경로·파노라마 및 지도 유형/촬영 도로, 실제 내장/외부 화면의 양방향 줌. 모의 SDK나 오프라인 QGIS 통과로 대체하지 않는다.
- **후속 확장:** API 결과 핀과 입력 핀의 별도 보관, 포트 대체/재접속 상태 복원, 표시 레이어 관리자·이력 저장소의 독립 controller 전환. 현재 입력 좌표와 기존 이력 계약을 유지하며, 이 항목들은 이번 적용 완료로 표시하지 않는다.
- **비교 UI:** 카카오 비교창에서 NAVER GPKG를 사용하는 기존 방향을 유지한다. NAVER 자체 비교창 복제와 서비스 간 동일 옵션 보장은 이번에 추가하지 않았다.
- 릴리스 판단과 패키지 생성은 별도다. 실제 수동 매트릭스, 키 제외 및 ZIP 구조 확인 후 진행한다.
