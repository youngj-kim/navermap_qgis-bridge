## 비교 기준과 범위

- NAVER: 이 저장소의 현재 작업 트리, 메타데이터 `0.2.0`.
- Kakao: `E:/Project/kakao_qgis-bridge-main`의 현재 작업 트리, 메타데이터 `1.2.2` 개발 후보. README와 실제 Python/웹 소스를 함께 확인했다. 원격 최신 릴리스와 동일하다고 가정하지 않는다.
- 시작 시 NAVER에 이미 미커밋 변경과 요금 연동 후보가 있었다. 이 검토는 해당 변경을 포함한 현재 소스를 대상으로 하며 기존 변경을 수정하지 않았다.
- 이번 결과물은 검토 문서다. 기능 구현, 리팩터링 적용, 버전 변경, 패키징, 커밋은 수행하지 않았다.
- 아래에서 코드로 확인한 위험과 실제 실행으로 재현한 항목을 구분한다. QGIS 3.34/4 및 실제 NAVER 화면 검증은 이번에 수행하지 않았다.

## 우선 수정할 발견사항

### 1. [P1] 복수 회피 선택이 실제 요청과 결과 설명에서 다르다

근거: `api_protocol.py:17–22`, `web/navermap_viewer.html:42–44`, `search_routes.py:493–496`.

무료 우선과 자동차전용도로 회피를 모두 선택하면 `route_option()`은 무료 우선 하나만 전송한다. 경로 유형도 회피 옵션에 의해 대체되지만 결과 메시지에는 선택한 유형과 두 회피 옵션을 모두 표시하고, 이력에도 모두 저장한다. 실제 적용 조건을 사용자가 오해할 수 있다.

수정 방향: 단일 경로 옵션 선택으로 UI를 정리하고 요청한 옵션·실제 적용 옵션을 일치시킨다. 여러 대안 조회는 별도 기능으로 설계한다. 공식 API의 `option`에 최대 3개를 전달하는 기능은 옵션별 경로 결과를 얻는 방식이며 두 회피 조건을 AND로 결합한다고 해석하면 안 된다. 기존 이력의 복수 선택값은 원본을 보존하고 적용 조건 불명으로 취급한다.

### 2. [P1] 하이패스가 실제 API 요청에 반영되지 않는다

근거: `api_protocol.py:30–43`, `search_routes.py:281–285,501–502`, `web/navermap_viewer.html:64`.

하이패스는 UI에서 선택하고 이력 및 완료 메시지에 남지만 요청 생성 함수의 인자·쿼리에 포함되지 않는다. 공식 Directions 5 요청 파라미터에도 하이패스 항목이 없다.

수정 방향: 경로 계산 설정에서 제거하거나 비활성화하고 미지원 이유를 표시한다. 기존 파일의 `car_hipass` 필드는 읽기 호환을 위해 보존하되 경로 계산에 반영됐다고 표시하지 않는다.

위 두 항목의 API 근거: [Directions 5 요청/응답 명세](https://api.ncloud-docs.com/docs/application-maps-directions5). NAVER의 `tracomfort`는 편한 길이며 최단거리가 아니다. 내부 `DISTANCE` 값은 기존 이력 호환용으로만 다루고 카카오의 최단거리와 동일 조건으로 비교하지 않는다. 카카오의 페리·어린이보호구역·유턴 회피도 현재 NAVER 명세에서 대응 요청값이 확인되지 않으므로 그대로 추가하지 않는다.

### 3. [P1] 프로젝트 전환 후 이전 요청이 현재 프로젝트에 적용될 수 있다

근거: `plugin.py:initGui`, `search_routes.py:377–381`, `map_layers.py:_ensure_roadview_layer`.

NAVER에는 프로젝트 전환 신호 처리와 프로젝트 세대 번호가 없다. 응답 함수는 현재 reply인지 확인하지만 프로젝트가 바뀌었는지는 확인하지 않는다. 이전 프로젝트에서 조회한 요청이 새 프로젝트에 경로·안내 레이어를 만들거나, 외부 브라우저에 대기하던 이벤트가 새 프로젝트에 적용될 위험이 있다. 코드 경로로 확인한 위험이며 실제 QGIS 전환 재현은 미수행이다.

수정 방향: 프로젝트 전환 시작 시 세대 번호 증가, 진행 요청 취소 및 이벤트 수신 중단; 완료 시 표시 레이어 참조·웹 경로 입력/안내 초기화. 요청/응답·외부 이벤트·파일 대화상자 복귀 시 세대 확인. 세션 이력은 유지한다. 레이어 하나를 삭제하는 동작과 프로젝트 전환은 구분한다. 카카오의 `_begin_project_transition()`/`_finish_project_transition()`은 설계 참고점이다.

### 4. [P2] 좌표 검색 후 이전 장소 검색 결과가 다시 표시된다

근거: `web/js/search.js:171–198`.

`searchLocal()`은 좌표 입력을 즉시 처리한 뒤 반환하므로 `searchRequestId`가 증가하지 않는다. 이전 장소 검색 Promise가 완료되면 아직 최신 요청으로 판정되어 결과 목록과 상태 메시지를 덮어쓴다. 실제 함수 본문을 Node VM에서 실행해 ‘장소 검색 시작 → 좌표 선택 → 이전 검색 완료 → 이전 결과 렌더링’을 재현했다.

수정 방향: 좌표 처리 전에도 세대 번호를 증가시키고 검색 버튼 상태를 정리한다. 새 좌표/입력/프로젝트 전환 후 늦은 응답이 UI를 덮어쓰지 않는 회귀 검증을 추가한다.

### 5. [P2] 경로 요청이 끝나지 않으면 입력창이 계속 잠길 수 있다

근거: `api_transport.py:19–23`, `web/js/sdk_events.js:439–490`, `web/js/route_inputs.js:65–87`.

검색에는 7초 제한이 있지만 경로에는 애플리케이션 수준의 시간 제한이 없다. 웹은 요청 전에 `routeBusy=true`로 설정하고 상태 응답을 기다리는 동안 초기화까지 비활성화한다. 응답이 지연되거나 bridge 응답이 누락되면 사용자가 UI에서 복구하기 어렵다. 실제 네트워크 지연 재현은 미수행이다.

수정 방향: 명시적 경로 시간 제한·취소 계약을 도입한다. 취소/시간 초과/프로젝트 전환/종료 때 요청 소유권을 먼저 해제하고 두 뷰어 모두 busy 상태를 해제한다. 유료 요청의 자동 재시도는 기본으로 추가하지 않는다.

## 리팩터링 방향

현재 파일 분리는 유용하지만 `*Mixin`이 같은 플러그인의 레이어·요청·UI 상태를 공유한다. 모듈 분리만으로 상태 소유권이 독립된 것은 아니다. `ApiTransport`, `ViewerMessages`, 순수 변환 함수와 공통 문서 조립기는 유지한다.

| 대상 | 현재 문제 | 다음 책임 경계 |
| --- | --- | --- |
| 경로 입력/응답 | 검증·API·QGIS 레이어·이력·메시지가 `search_routes.py`에 함께 있음 | Qt 없는 요청 검증/결과 정규화 → 요청 수명 → QGIS 표시 순서로 분리 |
| 표시와 이력 | 현재 표시 레이어와 세션 이력의 수명이 다름 | 표시 레이어 관리자와 이력 저장소를 분리. 프로젝트 전환은 표시만 초기화 |
| 이력 스키마 | 메모리 URI, 필드 매핑, SHP 단축명, GPX 확장에 정의 분산 | 공통 스키마/포맷별 매핑을 한곳에서 정의. 기존 파일 읽기와 NULL 요금 보존 |
| 내장/외부 bridge | 슬롯, JSON 키, Python 분기, JS 메서드의 계약이 여러 곳에 반복 | 명령 이름·필수 필드·검증기·dispatcher를 명시. 양쪽 전송 어댑터는 유지 |
| 외부 HTTP 서버 | 임의 POST 경로 수용, 본문 크기 제한/스키마 검증 없음, 입력 큐 무제한 | 경로 allowlist·JSON 객체 검증·본문/큐 한도. 이동 이벤트 병합, 상태 재접속 복원 검토 |
| 웹 모듈 | 파일은 나뉘었지만 manifest 순서와 공유 lexical 변수에 의존 | 검색·경로 입력·동기화부터 의존성을 인자로 받는 controller로 전환. 배포용 문서 조립은 유지 |
| 플러그인 진입점 | 설정창·액션·외부 이벤트 분기까지 보유 | 설정 UI와 dispatcher를 분리하고 초기화/종료/배선 중심으로 축소 |

새 controller에 기존 plugin 전체를 전달하면 같은 결합을 옮기는 데 그친다. 필요한 저장소·뷰어 어댑터·콜백만 전달한다. QGIS/Qt 버전 차이는 `compat.py` 또는 명시적 런타임 분기에 격리한다. 이 검토에서는 카카오 코드를 복사하지 않았다. 향후 이식 시 출처와 GPL-2.0-or-later 호환성을 확인한다.

## 권장 작업 순서와 완료 기준

1. **정확성/안정성:** 회피·하이패스 표시 수정, 좌표 검색 응답 역전 차단, 경로 취소/시간 제한, 프로젝트 전환 계약. 늦은 응답·취소·전환·unload 회귀 검증 및 실제 QGIS 3.34 외부/4 내장 검증.
2. **지도 사용성:** 탐색창/결과 접기, 지도 유형/촬영 도로, 도크 분리 크기, 축척 동기화. 줌만 변경할 때 파노라마 위치 유지, 네 가지 배치·좁은 창·분리/재도킹 확인.
3. **데이터와 확장:** 이력 스키마 통합, 표시 핀/입력 분리, 포트 대체·재접속 복원, 필요 시 NAVER 비교창. 요금 NULL/0, 구버전 이력, 네 가지 내보내기 및 카카오 비교창 왕복 검증.
